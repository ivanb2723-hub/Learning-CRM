## 1. 样本结构：一份身份、两种找法

- `MIN-SYS01` **System Overview**：解释“CRM 员工提出问题 → 系统确定模型与可用能力 → 读取业务/知识数据 → 形成回答 → 检查结果”的**学习导览**；不是 CRM 源码模块树，也不要求独立七字段长文。

## 5. 三种阅读密度的实样

### 5.1 完整七字段：MIN-K03 模型调用 Context（S2+ 候选）

1. **一句话定义**：模型调用 Context 是模型在**这一次调用**实际可见的指令、消息、工具描述和相关材料；下一次调用的内容可以不同。此处特指 *model context*，不把框架的 *runtime context* 配置字段混为一谈（`E-CTX`）。
2. **Why**：Agent 的状态、知识库和业务数据可能远多于模型这次需要的材料。选择相关信息能降低遗漏关键依据、超出输入容量、泄露无关数据与不必要成本的风险；效果是否改善需用任务和成本指标验证，不能由概念本身保证。
3. **原理 → 项目落地**：`任务/规则＋选中的会话信息＋相关 Tool/FAQ 结果 → 选择、裁剪、组织 → 模型调用`。这是 `QC005` p14 的课堂机制和 `E-CTX` 的模型输入边界。CRM 审计 `§5.1/§5.4` 可证上下文展示与模型配置；**具体某次调用选择了哪些 FAQ 片段、顺序、裁剪策略没有现有审计证据**，请原项目 Codex 按请求/中间件/模型事件核验。
4. **关键边界／易混淆点**：Context ≠ 全部 State；State 中可有未送入模型的 Todo/结果。Context ≠ 长期 Memory 存储；记忆可经检索后被选入一次 Context。Context ≠ 单一 System Prompt，也不等于标称 Context Window 大小。课件说的“运行时 Context”与框架 `runtime.context` 的专有配置 API 需分别注明。
5. **Case**：Case-01 的第 4 步只问“哪些 FAQ 证据进入本次输入、哪些未进入”；跳转到 Case 展示过程，不在这里复制五步轨迹。没有真实请求时只显示“待核”字段，不造一份模型输入。
6. **Interview Lens**：练习问题“对话一长开始答非所问，你会怎么定位和处理？”来自 `XHS-015`（SRC-02 原文行 94，个人自述未核实）。回答思路：先区分检索没找到、找到了但未送入、被截断/排序淹没、模型仍误用信息；提出可观测证据与对照验证，不能声称云帆已完成这些诊断。
7. **Evidence**：课程 `QC005`（`libfile_2fc39d93375c8191b6c280d3f33a6cbf` 幻灯片 14）、`QC006`（同源幻灯片 16）；专业 `E-CTX`；项目 `P-ENG §5.1、§5.4`；岗位 `XHS-015`。**证据边界**：项目真实组装与效果待原项目 Codex 核验。

### 5.2 简短阅读：MIN-K05 Checkpoint（S2 或机制旁注）

> **是什么**：在 LangGraph 线程运行中保存 State 快照，支持暂停与后续恢复等能力（`E-PER`）。  
> **与谁有关**：K04 State 经 L07 被保存；在 CRM 本地审计中，`SqliteSaver` 与 checkpoint 表有证据（`P-ENG §5.5`）。  
> **不能推断**：课件 p16 只讲 Run State；数据库有快照不等于任何故障场景都恢复成功，本轮未复现。深入机制可跳专业文档或待核工程证据。

## 8. 问题裁决与停止线

1. **是否真的需要三级以上？** 当前证据支持 RAG 整体机制 → 检索步骤 → CRM 应用这一条三级**学习展开**；只在限定路径中有 K08 `part-of` K07 的真正组成关系。第三级是应用而非子类。没有证据强迫所有知识有三级、四级或五级严格父子。
2. **地图与详情的分工**：整体系统和高辨识概念可作 S1 锚点；状态快照、检索子步骤与项目具体应用通常更适合详情、Case 或证据。这里是待测的显示假设，非最终 S1 列表。
3. **两条入口一份内容**：概念、课程 Claim、项目证据、面试题各有身份和关系；系统位置是引用，不占有概念。CRM 实例 `applies` RAG，不把所有 RAG 变成 CRM 零件，也不把 SQL 从通用基础中抹掉。
4. **最小路径够不够测？** 13 个对象＋一例可检验跨分面发现、三级深度、非树边、七字段/短读/导航三种密度和项目证据分离。它不能证明整个 70 份资料覆盖、完整 Node Inventory 或真实用户理解效率。
5. **不能进正式开发的争议**：F1/F2 名称与五领域边界；K08 检索子机制在其他 RAG 范式的范围；K10 的真实模型输入、检索结果和效果；Context 具体组装；Checkpoint 恢复范围；K11 SQL 的课程教学深度；S1 哪些对象应成为可见节点；旧 H02/H06 是否迁移复用及 ID 映射；完整 JD/面经核验。关系 L02/L05/L10/L12/L13 为研究建模或设计目标，工程直接证据与适用范围需进一步审查。
