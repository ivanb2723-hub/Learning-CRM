# P1 最小新知识结构隔离兼容性测试计划

## 边界

- 基线来源：原开发环境的 2026-10-12 保护快照（未随仓库发布）
- Sandbox：原开发环境的 P1 兼容性测试目录（未随仓库发布）
- 独立 Origin：`http://127.0.0.1:5275`
- 所有 fixture、适配器、测试记录均限制在 `experiments/p1/`；不回写正式工程。
- 不读取或修改原 Origin 的 localStorage；迁移实验使用内存模拟 Storage。

## 阶段

1. 重新安装 Sandbox 依赖，并运行现有 test、typecheck、build，记录基线。
2. 建立 P1 样本 fixture，忠实保留对象类型、关系语义、内容密度与 Evidence 状态。
3. 直接用当前 Schema/Validator 做诊断，记录可接受项和拒绝项。
4. 先写失败测试，再实现最小实验适配器，验证：
   - 统一知识身份及多入口引用；
   - 导航层级与技术关系分离；
   - 多对象类型和多语义关系；
   - S1 投影模型；
   - S2/S2+ full / short / navigation 三种密度；
   - Case / Interview / Evidence 引用；
   - 旧 ID、Card、学习进度与 H02 编辑数据 dry-run 迁移。
5. 在 5275 端口启动 Sandbox，用独立浏览器 Origin 验证 S0 → S0-L → S1、返回与共享壳层；不向正式数据注入 P1 样本。
6. 复跑 test、typecheck、build；复核受保护 999 文件与快照一致，并形成报告。

## 判定口径

- 直接通过：当前正式代码无需修改。
- 隔离实验通过：仅在最小实验适配后通过。
- 静态可行：代码结构支持判断，但未完成动态验证。
- 需要结构性修改：需改正式 Schema、数据链、布局或组件。
- 阻塞/未知：无法在当前边界内安全确认。
